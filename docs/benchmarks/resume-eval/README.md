# KV-Fabric 简历专项实测

2026-11-24 · 基线 06b7f28 及当日工作区

在单台 Intel(R) Core(TM) Ultra 7 265KF / RTX 5060 Ti 主机的 Ubuntu 22.04 WSL2 上运行。构建、测试和文件样本均位于 WSL2 的 /dev/sdd ext4 虚拟盘。推理使用 127.0.0.1 TCP，目录、发布 Worker 与消费 Worker 进程独立，两个 Worker 使用同一张 GPU。仓库本体位于 Windows C 盘的 9p 挂载，源码副本、构建与基准读写均迁入 ext4。

使用本机缓存的 Qwen2.5-3B-Instruct 权重，参数数为 3,085,938,688。临时模型适配保留 BF16 权重和 FP32 前向累加及 KV，重排 Q/K 的 RoPE 维度并接入 QKV 偏置、RoPE theta 与 RMSNorm epsilon。请求使用官方词表预编码。当前仓库的原生加载器读取 legacy Llama FP32，Qwen 适配在独立副本中完成，限制为 2,048 Token。目录、页协议、连接池、异步预取、CUDA 页导入和调度沿用仓库实现。

归档样本对应 `06b7f28` 加当日工作区的 rsockets 改动，实验走 TCP 数据面。公开复跑使用 `06b7f28` 自带的 TCP 路径，采用相同的模型、负载和计量定义。[源码快照](source-snapshot.csv) · [模型与词表哈希](model-provenance.csv) · [构建环境](environment.csv) · [复现命令](REPRODUCE.md) · [Qwen2.5-3B-Instruct 官方模型说明](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct)

另以原始 Safetensors 的 Transformers FP32 前向核对 3 条 512 Token 输入，每条贪心生成 8 Token。相同序列 3/3，见 [qwen-reference.csv](qwen-reference.csv)。该组用于转换核验。

## A 长前缀端到端 TTFT

并发 1，512 Token 输入、448 Token 共享前缀（87.5%）、32 Token/页，greedy 生成 8 Token。三种模式每组 30 次，按 10 次一组轮转模式顺序。先预热无关输入。Remote 每次用生产 LRU 路径清除消费端索引并等撤销队列收尾，测点在已编码请求就绪后、首次采样完成时结束。

每 Token 的 FP32 K/V 是 72 KiB。一页是 2.25 MiB，8 页和 8 MiB 两个上限共同使实际窗口最多 3 页，14 个远程页分为 3 + 3 + 3 + 3 + 2。消费端每次实收 33,030,144 字节，完整提示的 16 页均计算并存档 SHA-256，生成的 8 个 ID 逐位与 Cold 匹配。

## B 并发对话回放

以同一次真实生成构造三轮对话历史，测量后两轮。前一轮提示分别有 32、64 Token，追加该轮生成的 4 Token 和新用户内容后，消费提示为 64、96 Token，目标请求各生成 4 Token。不同对话的第一页不同。相同并发、轮次和样本在三种模式使用相同输入。

每种模式和并发度、每个被测轮次均采 16 个请求组，先用无关输入预热。Remote 在每组前清除消费端索引，Local 在每个配置的采样前加载前一轮对应前缀。吞吐以请求数或 Token 数除以各组实际处理时长之和。总 Token/s 含输入与输出，有效 Prefill Token/s 用输入 Token 总数除以各组最迟 Prefill 完成时间之和。两者均将复用 Token 视为已服务的输入，实际前向数另计。时间包含排队、目录查询、远程导入、Prefill 和 Decode，排除模型启动、预编码、前一轮产出缓存与测后核验。吞吐统计衡量消费 Worker 的闭环请求组。

## C 等口径 O_DIRECT 文件基准

4 MiB 有效载荷。Direct POSIX 和 Direct io_uring fixed 均走同一 ext4 对齐记录格式，执行写入、回读、CRC 与逐字节校验。每种配置先预热，每线程每轮采 16 次，共 3 轮。32 线程组用子进程 256 MiB memlock 确保注册成功，日志分别确认 direct-posix 和 direct-uring-fixed。有效总带宽为双向有效字节数除以每轮墙时，表中取 3 轮中位数。单次写、读速率分别用字节总数除以对应调用耗时总和，适用于单请求阶段口径。
