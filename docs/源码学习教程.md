# MiniInfer C 源码学习教程

从 `examples/basic.c` 开始，跟踪同一个 4 KiB 数据块如何在 CPU 内存中创建、写入、提交，再迁移到文件后端。读懂这条链路后，再用两个测试学习 KV 卸载和前缀复用。这份教程讲 MiniInfer Storage 产品，学习对象是数据的地址、版本、放置和生命周期。示例和测试用固定字节模拟调用方交给存储层的 KV 数据。

## 1. 编译、运行，找到入口

Windows 下在 WSL 的 Ubuntu 终端执行以下命令。在 Linux 下，从项目根目录执行 `cmake` 开始的几行。

```bash
cmake -S . -B build-debug -DCMAKE_BUILD_TYPE=Debug -DMINIINFER_WITH_KVFABRIC=OFF
cmake --build build-debug -j
./build-debug/bin/miniinfer_basic
ctest --test-dir build-debug --output-on-failure
```

示例输出 `block 1 is now on SSD (version 1)`。这里的 `1` 是示例在 `printf` 中写死的版本值，第 4 节会用调试器读出实际元数据。测试以 `assert` 为主，保留 Debug 构建可以让断言及其内部调用参与执行。`CMakeLists.txt` 把核心模块编成静态库 `miniinfer_storage`，示例和测试分别链接它。默认构建只需要 C11、POSIX 和 pthreads。

## 2. 顺着 `main` 读一遍写入路径

先打开 [tiered_storage.h](../include/miniinfer/tiered_storage.h) 和 [common.h](../include/miniinfer/common.h)。`typedef struct mi_tiered_storage mi_tiered_storage;` 只公开类型名，结构体定义在 `.c` 文件里。调用者拿 `mi_tiered_storage *` 并通过 API 操作内部状态。`mi_tiered_storage_create(cfg, backends, &storage)` 返回 `mi_status`，用 `&storage` 这个输出参数交回对象地址。`mi_lease` 的定义直接公开，调用方可以在栈上声明它，并访问 `lease.data` 和 `lease.size`。

### 2.1 从 `id` 找到内存地址

从 [basic.c](../examples/basic.c) 顺着直接调用往下追。

1. `mi_mempool_create(MI_MEMORY_CPU, -1, ...)` 创建 CPU 内存池。`mi_memory_backend_create(..., 16, &cpu)` 从池中申请一个连续 Slab，切成 16 个物理槽。本例分层存储的 CPU 预算只开放其中 4 个槽。
2. `mi_storage_create_block` 调用 `mi_backend_reserve`，后端弹出空闲物理槽并返回句柄。分层存储再从自己的空闲栈取逻辑记录，保存位置、大小和物理句柄。
3. `mi_storage_acquire` 调用 `record_at`，用 ID 的低 32 位减 1 定位逻辑记录，再校验完整 ID。申请 WRITE 时，`mi_backend_reserved_ptr` 用句柄定位槽位，计算 `base + slot_index * stride`。`memcpy` 直接写 `lease.data`。
4. `mi_lease_finish` 进入 `lease_complete`，提交已初始化的数据，将版本从 0 增至 1，并清空租约。

逻辑 ID 与物理句柄各自编码代数和槽位。后端之间可以出现数值相同的句柄，因此从逻辑 ID 找到位置后，还要用对应后端解释物理句柄。

### 2.2 用 `lease_complete` 理解租约

创建后的块处于 `RESIDENT`，版本为 0，`initialized` 为 0。`RESIDENT` 表示块有一个驻留位置，读权限还取决于初始化和租约状态。把 [mi_storage_acquire](../src/worker/tiered_storage.c) 的判断按这个表重读一遍。

| 操作 | 需要满足的条件或产生的变化 |
| --- | --- |
| 获取 READ | 块已初始化且无写者时，可以同时有多个读者。 |
| 获取 WRITE | 当前没有活跃租约。取得后立即清掉 `initialized`，调用方原地写入。 |
| `finish` WRITE | 设置 `initialized`，增加版本，结束租约。 |
| `abort` WRITE | 结束租约，保留原版本号，数据保持未初始化。下一次完整写入可以重新提交。 |
| GPU 租约 | 传入非空 `mi_stream`。结束租约前通过 `mi_device_stream_wait` 同步，等待失败时租约仍然有效。CPU 租约传 `NULL`。 |
| SSD 上的块 | 用 `mi_storage_read_to_host` 拷回调用者缓冲区，或迁回内存后取得租约。直接 `acquire` 返回 `MI_ESTATE`。 |

上层对象会借用下层对象。结束租约、处理迁移票据，销毁序列和 KV 对象，再销毁分层存储、后端和分配器。`examples/basic.c` 结尾的释放顺序就遵循这条依赖链。

## 3. 跟进 `mi_storage_migrate` 和文件后端

### 3.1 CPU → SSD 的提交点

在 [tiered_storage.c](../src/worker/tiered_storage.c) 中定位 `mi_storage_migrate`。拿着 `id=1`、`size=4096`、`version=1` 读这三个阶段。

1. **准备。** 持有 `s->mutex` 时检查源块状态与租约，快照保存元数据和源句柄，将块标为 `MOVING`。
2. **搬运。** 释放 `s->mutex` 后从目标后端的空闲栈预留物理槽。CPU → SSD 直接将 CPU 槽地址传给 `mi_backend_write_record`。GPU ↔ SSD 使用预留的 Pinned Slab 槽中转。
3. **提交。** 重新拿锁后更新物理句柄和驻留位置，将状态改回 `RESIDENT`，并释放源槽或保留 SSD 副本。逻辑 ID 和数据版本随迁移保留。

逻辑记录数组在创建分层存储时固定。迁移用 `busy` 阻止同一记录被访问或回收。切换前失败时，目标槽释放失败会返回 `MI_EROLLBACK_CLEANUP`。切换后释放源槽失败会返回 `MI_ECLEANUP`。两种情况都可调用 `mi_storage_retry_cleanup`。

本例只有一块数据。各层用字节预算除以物理槽大小得到槽数上限，并用 `free_slots` 跟踪剩余配额。下表将占用换算为字节。

| 时机 | CPU 已占用 | SSD 已占用 | 元数据 |
| --- | ---: | ---: | --- |
| 创建完成 | 4096 | 0 | CPU，`RESIDENT`，版本 0 |
| 第一次写提交 | 4096 | 0 | CPU，`RESIDENT`，版本 1 |
| 预留目标层后 | 4096 | 4160 | CPU，`MOVING`，版本 1 |
| 切换并清理源槽后 | 0 | 4160 | SSD，`RESIDENT`，版本 1 |
| 擦除后 | 0 | 0 | `id` 对应的记录已移除 |

[test_tiered.c](../tests/worker/test_tiered.c) 接着把块从 SSD 异步迁回 CPU。`max_async_migrations` 限制排队和执行中的任务总数。worker 调用同一个 `mi_storage_migrate`，把状态码存进 ticket。调用方用 `mi_migration_wait` 取回状态码，再销毁自己的 ticket 引用。`mi_storage_migrate_batch` 按顺序写回每个块的状态码。

这个测试还开启了 `mi_storage_config.retain_ssd_copy`。从 SSD 迁回内存时，`block_record.replica` 保存原 SSD 槽的句柄，继续占用 4160 字节的预算。下一次 WRITE 租约结束时清理旧副本，成功释放后才把槽还给预算。

### 3.2 文件里写了什么

打开 [storage_backend.c](../src/worker/storage_backend.c)，跟着 `mi_backend_write_record → publish → ssd_transfer` 读一次写入。

| POSIX 和 io_uring 记录布局 | 计算 |
| --- | --- |
| 步长 | `slot_bytes + 64` |
| 记录起点 | `((uint32_t)handle - 1) * stride` |
| 数据起点 | 记录起点加 64 字节 |

`publish` 计算 CRC32C，编码 64 字节头部，然后将头部和 payload 一起交给 `ssd_transfer`。传输成功后槽位才标记为已封存。`mi_backend_read_validated` 核对格式、块 ID、版本和大小，`MI_SSD_VERIFY_ON_READ` 还会核对 CRC32C。

`ssd_transfer` 按后端类型调用 POSIX、io_uring 或 SPDK。POSIX 在 [file_io.c](../src/worker/file_io.c) 用 `preadv` 和 `pwritev` 处理短读写和 `EINTR`。SPDK 将槽步长向上对齐到 4096 字节，通过自己的 DMA 缓冲区完成块设备 I/O。`mi_ssd_backend_create(NULL, ...)` 创建并立即解除链接一个临时文件，文件描述符保留到后端销毁。

## 4. 用 GDB 观察实际版本和位置

先完成第 1 节的 Debug 构建，再从项目根目录运行 `gdb -q ./build-debug/bin/miniinfer_basic`。在 GDB 提示符下依次输入以下命令。

```gdb
break mi_lease_finish
run
print lease->id
print lease->size
x/8bx lease->data
break mi_storage_migrate
continue
print target
print s->records[(uint32_t)id - 1].meta
finish
print storage->records[(uint32_t)id - 1].meta
continue
quit
```

第一个断点停在写入之后、提交之前，能看到 `id=1`、`size=4096` 和连续的 `0x5a`。第二个断点刚进入迁移函数，元数据应为 `CPU/version=1`。`finish` 返回示例后，GDB 会显示 `MI_OK`，块的元数据应为 `SSD/version=1`。

## 5. KV 卸载如何选择要搬走的数据

Transformer 解码会把已处理 token 的注意力 K/V 保存下来供后续 token 使用。这里 `mi_kv_cache` 接收调用方给出的字节和逻辑槽位号，内部用 `entries[slot].id` 找分层存储中的块。读 [kv_cache.c](../src/worker/kv_cache.c) 时把 `slot`、`id` 和后端 `handle` 分别记在纸上。迁移保留 `id`，同一逻辑槽被覆写时则可能分配新的 `id`，新块的 `size` 也可以变化。

[test_kv_cache.c](../tests/worker/test_kv_cache.c) 把 CPU 预算设为 4096 字节，每个写入也是 4096 字节。按测试顺序手推一次。

| 测试操作 | CPU | SSD | 进入的主要函数 |
| --- | --- | --- | --- |
| 写 slot 0，内容 `0x11` | 0 | 空 | `mi_kv_cache_write` |
| 写 slot 1，内容 `0x22` | 1 | 0 | `make_room` 先迁出 0，再创建 1 |
| 读 slot 0 | 0 | 1 | `promote` 先迁出 1，再迁回 0，最后拷到输出缓冲区 |
| 异步预取 slot 1 并等待 | 1 | 0 | `prefetch_worker → promote` |

`make_room` 通过 `mi_storage_has_room` 查询 CPU 层容量。空间不足时直接取 CPU 驻留 LRU 的头项。读入或写入一个 CPU 槽后，将它移到 LRU 尾部。缓存的同一把互斥锁保护 LRU、逻辑槽和预取队列。

异步任务携带 `(slot, id)`。worker 对比完整 ID，识别已删除或被覆盖的槽位。`prefetch_queue_depth` 限制预取队列，同一槽已有待处理任务时会去重。

```bash
ctest --test-dir build -R '^kv_cache$' -V
```

## 6. Paged KV 如何共享前缀

打开 [paged_kv.c](../src/worker/paged_kv.c)。`mi_kv_sequence.pages` 保存页 ID。`page_blocks` 用页 ID 在连续的块表中定位各层块。前缀索引用父页 ID 和一页 token 做散列，命中后还会逐项核对 token。

[test_paged_kv.c](../tests/worker/test_paged_kv.c) 设置 2 层、每页 2 个 token、每层 4096 字节。

1. `mi_kv_sequence_append_page` 从固定空闲栈取页 ID，给这一页的两层各分配一个块。
2. `mi_paged_kv_acquire` 获取指定层的块租约。页租约也持有页引用，直到块租约结束。
3. `mi_kv_sequence_publish` 检查各层是否已提交，然后将 `[42, 43]` 对应的页封存并加入索引。封存页再申请 WRITE 会得到 `MI_ESTATE`。
4. `mi_paged_kv_match` 从根开始查找，原序列和命中序列共享同一个页 ID。查询 `[42, 43, 99]` 时，`matched` 为 2。
5. 销毁序列和清除前缀索引分别释放各自的引用。最后一个引用归零后，`page_release` 擦除各层块并把页 ID 推回空闲栈。

```bash
ctest --test-dir build -R '^paged_kv$' -V
```

## 8. 三个动手练习

1. **验证迁移后的内容。** 在 `basic.c` 的迁移完成后、擦除前，调用 `mi_storage_read_to_host`。检查返回值、`bytes_read == 4096` 和 `memcmp(data, readback, 4096) == 0`，再用 `mi_storage_metadata` 核对位置仍为 SSD。参考 `test_tiered.c` 的现成调用。
2. **改变 CPU 预算。** 把 `test_kv_cache.c` 的 `sc.cpu_bytes` 从 4096 临时改成 8192。在 `make_room` 内的 `mi_storage_migrate` 调用处设断点，比较修改预算前后的迁移次数。两块都驻留在 CPU 时，预取 slot 1 仍会成功。
3. **验证前缀树引用。** 在 `test_paged_kv.c` 中把查询 token 换成 `[42, 43, 99]`、长度改为 3，保持发布仍为两个 token。验证 `matched == 2`。读完并结束页租约后，试着先清前缀树，再从 `hit` 获取 READ。只要 `hit` 还持有页引用，数据就能继续读取。

每次改完用 `cmake --build build-debug -j` 重编，再运行对应的示例或用 `ctest -R` 跑单项测试。最后合上源码，试着画出 `slot → id → (backend, handle) → lease.data`，并说明其中哪些值会在一次 KV 覆写、一次迁移和一次前缀匹配中变化。
